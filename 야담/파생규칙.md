# 야담 파생주제 규칙 v3

이 파일은 야담 유튜브 채널의 **파생주제 만들기** 작업 기준이다.
새 대화에서 사용자가 "파생규칙 파일을 읽고 시작"이라고 하면
이 파일을 처음부터 끝까지 읽고, 모든 규칙을 따른다.

---

## 0. 작업 개요

- 사용자는 참고 야담 영상의 **썸네일(이미지)과 제목**을 준다. 한 번에 10개, 20개가 될 수 있다.
- 썸네일 하나마다 서로 다른 창작 야담 **파생 기획 10개**를 만든다.
- 결과는 Google Sheets **"야담 소재 은행"**에 기록한다.
- 우리 콘텐츠는 한국 50~70대 성인·시니어가 듣는, 옛날을 배경으로 한 **창작** 이야기다.
- 지금은 **파생 기획까지만** 만든다. 긴 대본은 쓰지 않는다.
  (대본은 Claude 프로젝트의 PROMPT 1 → 3 → 2에서 따로 만든다.)

---

## 1. 처리 순서 — 한 번에 썸네일 1개

썸네일을 여러 개 받아도 **한 번에 1개씩** 처리한다.

1. 받은 썸네일 전체에 번호를 붙여 목록을 먼저 보여준다. (예: `[1/15] 다리 마비로 쫓겨난 여종`)
2. 1번 썸네일만 처리하고 시트에 기록한다.
3. 끝에 `[1/15 완료] "다음"이라고 하시면 2번으로 넘어갑니다.`라고 안내한다.
4. 사용자가 "다음"이라고 하면 다음 썸네일을 처리한다.

이유: 여러 개를 한 번에 처리하면 뒤로 갈수록 기획이 짧아지고, 비슷해지고, 검사가 느슨해진다.

---

## 2. 기본 원칙 — 무엇을 배우고 무엇을 새로 만드는가

> 시청자가 궁금해한 **이유(장치)**는 참고하고,
> 그 궁금증을 만드는 **사건은 새로** 짠다.

| 참고하는 것 (가져와도 됨) | 새로 만드는 것 (가져오면 안 됨) |
|---|---|
| 이상해 보이는 행동의 이유를 뒤에서 밝히는 구성 | 인물, 관계, 직업 |
| 사람들이 놓친 모순을 질문으로 드러내는 구성 | 핵심 물건과 그 기능 |
| 이해하기 어려운 행동에 과거 인연을 연결하는 구성 | 사건 배열, 반전, 클라이맥스, 결말 |

금지:
- 다른 채널의 대사·고유한 장면을 가져와 이름만 바꾸는 것
- 썸네일·제목에 없는 원본 줄거리, 속마음, 숨겨진 사정, 결말을 실제 내용처럼 설명하는 것
- 채널 규모·조회수를 추정하는 것 (사용자가 주거나 이미지에 보이는 정보만 사용)

## 3. 1단계 — 썸네일·제목 읽기

글자가 잘리지 않고 읽히는 범위에서만 확인한다. 읽을 수 없는 부분은 임의로 채우지 않는다.

① 등장인물과 관계
② 눈에 보이거나 제목에 명시된 행동·사건
③ 이상하거나 예상과 어긋나는 점
④ 시청자가 클릭해서 확인하고 싶을 질문

---

## 4. 2단계 — 원본 거리 검사 (HARD RULE)

기획을 만들기 **전에** 원본의 핵심 요소 5가지를 먼저 적는다.

| 주인공 | 상대 인물과 관계 | 핵심 물건 | 핵심 행동 | 시간 장치 |
|---|---|---|---|---|

예: 노총각 / 죽은 여인 / 짚신 / 짚신을 벗어 신겨줌 / 백 일 뒤 가마

- 10개 기획은 각각 이 5가지 중 **최대 2개까지만** 남기고 나머지는 새로 정한다.
- **3개 이상 남은 기획은 다시 만든다.**
- 원본에 해당 요소가 없으면 "없음"으로 적고 검사에서 뺀다.
- 각 기획마다 `원본 요소 남은 수`를 적는다.

나쁜 예 (원본에 너무 가까움):
```
원본: 죽은 여인에게 짚신 벗어준 노총각, 백 일 뒤 대문 앞에 멈춘 가마의 정체는?
파생: 죽은 여인에게 짚신을 신겨준 노총각, 백 일 뒤 찾아온 가마가 밝힌 그녀의 정체
→ 5개 모두 남음. 질문만 바뀌었다. 다시 만든다.
```

좋은 예 (장치만 가져옴):
```
원본: 왕비인 줄 모르고 삭발시킨 11살 천재아이
파생: 관군이 찾던 여인에게 수염을 그려준 숯쟁이 아이
→ "쫓기는 사람을 아이가 엉뚱한 기지로 숨긴다"는 장치만 남음.
```

## 5. 3단계 — 10가지 방법으로 기획 10개

1번부터 10번까지 **각각 하나씩**, 서로 다른 기획을 만든다. 방법을 합치거나 생략하지 않는다.
각 방법은 **가장 크게 바꾸는 기준**이다. 나머지 요소까지 원본과 똑같이 유지할 필요는 없다.
하나를 바꿨으면 **뒤의 사건과 해결까지 다시 짠다.**

### ① 인물과 관계를 바꾸기
이름이나 직업만 바꾸지 않는다. 두 사람이 서로에게 바라는 것과 갈등하는 이유가 달라지게 한다.
누가 누구에게 무엇을 부탁하고, 왜 거절할 수 없는지까지 바꾼다.
(예: 스승과 제자 / 재혼한 부부 / 경쟁 상인 / 객주와 길손 / 마을 사람과 낯선 사람)

### ② 목표와 대가를 바꾸기
주인공이 얻거나 지키려는 것을 바꾼다. 그것을 이루려면 무엇을 포기하거나 감수해야 하는지도 정한다.
(돈, 인정, 자유, 재회, 안정 중 이번 사람에게 가장 절실한 것)

### ③ 갈등의 원인을 바꾸기
악인의 욕심만이 아니라 엇갈린 약속, 잘못 전한 말, 기한, 품질 문제, 관습, 서로 양보하기 어려운 사정도 원인이 된다.
악역을 넣으면 무엇을 얻으려고 어떤 일을 벌였는지 구체적으로 정한다.

### ④ 주인공의 선택을 바꾸기
따라갈지 거절할지, 숨길지 밝힐지, 떠날지 남을지. 결말 한 줄만 뒤집는 것이 아니라
바뀐 선택 때문에 당장 생기는 문제와 그 처리 과정까지 정한다.

### ⑤ 물건의 기능을 바꾸기
물건 이름만 바꾸지 않는다. 증거, 약속, 거래 조건, 기억, 오해의 원인, 장사 도구처럼 **사건에서 하는 역할**을 바꾼다.
매번 물건 속에서 재산이 나오는 결말로 만들지 않는다. 깨뜨려 돈을 찾는 장면만 반복하지 않는다.

### ⑥ 장소·생업·시간을 바꾸기
배경 이름만 옮기지 않는다. 그 장소의 사정, 생업 방식, 계절이나 기한 때문에 문제가 생기거나 해결되게 한다.
"이 장소와 이때가 아니면 생기지 않을 문제"를 하나 정한다.
(포구, 주막, 가마터, 산골, 우물가, 장터, 빈집 / 첫 장날, 혼례 전날, 첫눈, 장마, 마지막 배)

### ⑦ 숨겨진 진실을 바꾸기
처음에 어떻게 보였고 실제로는 무엇이었는지 새로 정한다.
"알고 보니 부자 / 높은 신분 / 착한 사람"에 몰리지 않는다. 정체, 동기, 오해, 거래의 진실 등으로 나눠 본다.
반전이 있으면 **실제 답과 앞에 심어둘 단서**를 함께 적는다.

### ⑧ 해결 방법과 보상을 바꾸기
누군가 나타나 대신 해결하거나 갑자기 재산을 얻지 않는다.
주인공의 관찰, 기술, 협상, 협력, 증언, 결단이 해결에 쓰이게 한다.
보상도 신뢰, 독립, 재회, 생계 회복, 자기 일, 명예 등으로 넓힌다.

### ⑨ 신비한 능력과 규칙을 넣거나 바꾸기
동물, 도깨비, 귀신, 꿈, 신비한 물건을 쓸 수 있다. **금지가 아니다.**
단, 무엇을 할 수 있고 무엇은 못 하는지, 지켜야 할 조건이나 대가를 먼저 정한다.
앞에서 보여준 능력과 약속이 뒤에서도 같은 방식으로 작동해야 한다.
결말에서 처음 등장한 능력으로 모든 문제를 해결하지 않는다.

### ⑩ 서로 다른 갈래를 결합하기
장사 + 동물 보은, 혼인 + 누명, 해학 + 재산 분쟁처럼 두 갈래를 잇는다.
중심 갈등을 하나 먼저 정하고, 다른 갈래는 그 갈등의 원인·단서·장애물·해결 중 하나를 맡긴다.
두 이야기를 차례로 늘어놓지 않는다. 한 갈래의 사건이 다른 갈래의 문제를 일으키거나 해결해야 한다.

## 6. 제목 규칙

제목은 **실제 기획에 있는, 눈에 보이는 구체적 행동**으로 쓴다.

좋은 예:
- 파혼당한 처녀가 혼숫감을 몽땅 장터에 내다 판 이유
- 쫓기던 여인의 비단옷을 진흙탕에 처박은 열세 살 소녀
- 혼례 사흘 전 그릇을 전부 깨뜨린 옹기장이

금지 형태:
- **"A 대신 B"** — 방법 이름(①인물 바꾸기)이 제목에 새어 나온 형태
- **"뜻밖의 대가", "진짜 이유", "이상한 규칙", "놀라운 비밀", "벌어진 일"**로 내용을 대신하는 제목
- **정체·신분·보상 내용을 제목에서 말해버리는 것** (예: "사실 왕실과 관련된 천재였다는 진실")
- "충격적인 비밀이 드러난다", "놀라운 일이 벌어진다"처럼 답을 감추는 문장으로 줄거리를 대신하는 것
- 50~70대가 한 번 듣고 이해하기 어려운 길고 복잡한 제목 (30자 안팎 권장)

## 7. 기획 출력 형식

각 기획은 아래 형식으로 쓴다. 각 항목은 한 문장 정도로 구체적으로.
기획 단계이므로 **반전과 결말까지 모두 공개**한다.

```
[번호와 파생 방법]
중심 갈래:
제목 후보:
출발 사건:
중간에 생기는 새 문제:
주인공의 결정과 행동:
해결과 실제 결말:
시청자가 궁금해할 질문:
참고 썸네일·제목과 달라진 핵심:
원본 요소 남은 수: (0~2)
```

## 8. 출력 전 비교·수정

10개를 서로 비교하고 고친다.

- 이름과 소품만 다르고 사건이 같은 후보 → 다시 만든다.
- 10개가 모두 가족 갈등이나 같은 반전으로 몰리지 않게 한다.
- **10개 기획의 주인공·핵심 물건·해결 방법이 서로 겹치면** 다시 만든다.
- 원본 요소가 3개 이상 남은 기획 → 다시 만든다.
- 제목 금지 형태가 있으면 → 고친다.
- 주인공이 계속 고통받기만 하지 않고 판단하고 행동하게 한다.
- 칼·피·학대·과도한 고통·성적 암시를 관심을 끄는 수단으로 쓰지 않는다.
- 옛날 배경과 설정한 세계의 규칙 안에서 앞뒤가 맞아야 한다.
- 어린이의 클릭을 유도하는 표현이나 포장으로 만들지 않는다.
- 참고 자료의 독특한 문구와 장면을 그대로 옮기지 않는다.

## 9. 추천 3개

마지막에 10개 중 더 발전시켜볼 후보 3개를 고른다. 각각 짧게:
- 궁금증이 분명한 이유
- 중간 사건을 확장할 여지 (장편 체급)
- 다른 후보와 구별되는 점

조회수가 잘 나올 것이라고 보장하지 않는다.

### 9-1. 뻔한 반전 피하기
각 기획마다 "이 설정이면 누구나 떠올릴 반전"을 한 줄로 적고, 그 반전은 쓰지 않는다.
결과 요약표에 `피한 뻔한 반전` 칸으로 보여준다.
(예: 바보 아씨 → "사실은 천재/귀한 신분" / 늙지 않는 할멈 → "요괴나 신선")

### 9-2. 겹침 확인
- 추천 3개는 무료 웹 검색으로 비슷한 이야기·영상이 있는지 확인하고, 결과와 출처를 표로 보여준다.
- 정말 비슷한 영상이 나왔을 때만 vidIQ 자막 확인(1회 5크레딧)을 쓴다. 쓰기 전에 남은 크레딧을 알린다.

### 9-3. PROMPT 1 붙여넣기용 블록
추천 3개마다 11장 형식의 PROMPT 1 블록을 채팅에 함께 보여주고, 시트 `PROMPT 1 블록` 칸에도 넣는다.

## 10. Google Sheets 기록

스프레드시트 이름: **야담 소재 은행** (사용자의 Google Drive)

없으면 새로 만들고, 있으면 기존 시트에 **아래로 이어서** 추가한다. 기존 행은 지우거나 덮어쓰지 않는다.

### 탭 구성

**원본** 탭 — 참고 영상 1개 = 1행
| 원본ID | 원본 제목 | 채널 구분 | 주인공 | 상대 인물과 관계 | 핵심 물건 | 핵심 행동 | 시간 장치 | 등록일 |

**파생 소재** 탭 — 파생 기획 1개 = 1행 (세로형)
| 원본ID | 방법 | 제목 후보 | 중심 갈래 | 출발 사건 | 중간에 생기는 새 문제 | 주인공의 결정과 행동 | 해결과 실제 결말 | 시청자가 궁금해할 질문 | 장편 여지 | 달라진 핵심 | 원본 요소 남은 수 | 추천 | 상태 | 업로드일 | 조회수 | 메모 | PROMPT 1 블록 |

- `방법`: ①~⑩
- `추천`: 추천 3개에 든 기획은 "★"
- `상태`: 처음엔 "대기" (이후 사용자가 설계중 / 대본중 / 업로드 완료 등으로 바꿈)
- `업로드일`, `조회수`, `메모`: 비워둔다
- `장편 여지`(J열): 추천(★) 행에만 쓴다. 중간 사건을 어떤 장면들로 늘릴지 한 문장.
- `PROMPT 1 블록`(R열): 추천(★) 행에만, 같은 행 칸을 이어 붙이는 수식으로 넣는다 (r = 행 번호).
  ```
  ="시작 방식: ③"&CHAR(10)&"가제: "&Cr&CHAR(10)&"기획:"&CHAR(10)&"- 출발 사건: "&Er&CHAR(10)&"- 중간에 생기는 새 문제: "&Fr&CHAR(10)&"- 주인공의 결정과 행동: "&Gr&CHAR(10)&"- 해결과 실제 결말: "&Hr&CHAR(10)&"- 시청자가 궁금해할 질문: "&Ir&CHAR(10)&"- 장편 여지: "&Jr&CHAR(10)&"분위기: (정하기)"&CHAR(10)&"글자 수: (정하기)"
  ```
- **추천 색 표시**: `제목 후보` 칸(C2:C1230)에 조건부 서식 `=$M2="★"` → 노란 배경 + 굵은 글씨.
  이미 걸려 있으므로 `추천` 칸에 ★만 넣으면 자동으로 칠해진다. 시트를 새로 만들 때는 이 서식부터 건다.
- **업로드 완료 색 표시**: `제목 후보` 칸(C2:C1230)에 조건부 서식 `=$O2<>""` → 연두색 배경 + 굵은 글씨.
  `업로드일`(O열)에 무엇이든 입력하면 자동으로 칠해진다. 이 규칙을 추천(★) 규칙보다 **위(우선순위 1번)**에 두어,
  추천이면서 업로드한 주제는 연두색으로 보이게 한다. (노란색 = 아직 안 만든 추천, 연두색 = 업로드 완료)
- 기록 뒤 다시 읽어 한글 오타(깨진 글자)를 확인하고 고친다.

**제작 현황** 탭 — 사용자가 직접 관리. 새로 만들 때 머리글만 만든다.
| 원본ID | 제목 | 상태 | 시작일 | 업로드일 | 조회수 | 메모 |

### 기록 전 확인
- 같은 원본 제목이 이미 **원본** 탭에 있으면 사용자에게 알리고, 이어서 만들지 물어본다.
- 기록 후 몇 행을 추가했는지와 시트 링크를 알려준다.
